Adobe Target에서는 SDK·공통 스크립트 삽입 방식을 설계하고, 고객사 Web/App 전 영역의 개인화 기반을 분석·정의합니다. Adobe Campaign 구축에서는 OOTB로 제공되지 않는 자연어 SQL 타겟 추출 LLM을 핵심으로 개발하고, 발송 피로도(Fatigue) 제어도 같은 구축 범위의 한 파트로 담당합니다.

Adobe Target 구축
  • SDK 및 공통스크립트 삽입 방식 설계
  • 고객사 Web/App 전 영역 개인화 기반 분석 및 정의
  • Adobe 시스템 간 API 연동 파이프라인 및 페이로드 개발 — 고객 행동 데이터 수집 파라미터 정의 · 전달 규격 수립, 페이지 / 액션 단위 트리거 조건 설계
  • 트리거 및 노출유형 컴포넌트(팝업, 배너 등)의 재사용 가능한 코드 제작 및 최적화 — 캠페인별 중복 개발 제거
  • 구축 산출물 표준화 — WBS · 구축항목 체크리스트 · 개발 가이드 문서
Adobe Campaign 구축
  • SQL 생성 LLM — 구축에서 담당한 핵심 개발 범위
    • OOTB 미제공 기능 신규 개발 — 자연어(NL) 입력으로 대상 고객 추출 SQL을 생성하는 LLM 기능 설계
    • 고객 데이터 스키마를 반영한 프롬프트 및 응답 검증 로직 구현
    • 마케터의 타겟 추출 의존도를 낮추는 셀프서비스 구조 확보 — 생성 결과의 솔루션 기능 자동 연동
  • Fatigue 제어 — 같은 Adobe Campaign 구축에서 담당한 발송 제어 파트
    • OOTB Typology(유형 규칙) 기반 제어의 제약을 보완하는 커스텀 로직 설계
    • 고객 데이터 · 요구사항 기반 제어 기준 정의 — 채널별 / 특정 영역별 발송 한도 및 우선순위 적용
    • 타겟팅 워크플로우에 공통 적용 가능한 형태로 모듈화

Adobe Campaign 발송 데이터를 자연어로 질의하고 리포트로 자동 시각화하는 MCP 기반 AI 분석 시스템을 1인 풀스택으로 개발. 확장 한계를 확인한 뒤 차세대 아키텍처를 테스트 버전으로 검증하고 종결.

AI 역할 분리
  • 초기 버전은 LLM이 리포트 HTML까지 직접 생성 → 동일 질의에 결과 편차, 검증 불가
  • LLM은 리포트 타입 / 조회 조건 / 데이터 인사이트 3종을 JSON으로만 반환하도록 역할 축소
  • 리포트 렌더링 · 차트 생성은 서버 템플릿 엔진이 전담하는 구조로 재설계
  • "AI가 틀릴 수 있는 범위"를 선택지 내로 한정하여 재현성 확보
Tool 라우팅 정확도
  • 기능 추가로 증가한 Tool을 핵심 7종으로 축소
  • 지표 · 기간 · 채널 · 그룹 단위 통계 Tool 4종을 다차원 통계 범용 Tool 1종으로 통합
  • 재사용 가능한 날짜 필터 조건 11종 규격화 (주중 / 주말 / 공휴일 포함·제외 / 특정 일자 / 일자 구간 / 홀짝일 / 특정 요일 등)
지표 신뢰성
  • 오픈율 · 클릭률 등 비율 지표를 DB 집계 단계에서 선계산(SUM 기반)하여 LLM 재계산 가능성 차단
  • 숫자 축약 표기 금지 등 응답 규격을 프롬프트 레벨에서 강제, Tool 원본 데이터만 사용
